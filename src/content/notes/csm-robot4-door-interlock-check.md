북서·북동·남동 도어가 열린 상태에서도 Robot #4가 움직인다는 현상을 확인하기 위한 점검표다. R#1, R#2, R#4를 모두 교체한 뒤 나타난 현상이므로, 기존 제어 신호와 새 로봇의 입출력 설정을 함께 확인한다. R#3 도어는 이번 점검에서 제외한다.

**도어를 열어도 로봇이 계속 움직였다면 해당 구역의 접근을 중지한다.** 설비를 안전하게 정지·격리하고 접근을 통제한 뒤 보전·안전 담당자와 함께 점검한다. 운전 중에 문을 열어 확인하지 않는다. 일반 HOLD 신호와 사람의 접근을 막는 안전 정지 회로는 각각 확인해야 한다.

## 현재 확인한 인터록 흐름

세 도어 입력은 Cathode1 PLC의 `ESTOP / MainRoutine / Rung 3`에서 R#1과 R#2의 도어 정상 비트를 만든다. 셋 중 어느 하나라도 입력이 0이면 `Robot1_ESTOP`과 `Robot2_ESTOP`이 0이 된다. 이름과 달리 이 렁에서는 두 비트가 1일 때 세 도어 조건이 모두 만족된 상태다.

| 도어 | Cathode1 입력 | 입력 확인 위치 |
| --- | --- | --- |
| 북서 | `N4:2:I.15` | `ESTOP / MainRoutine / Rung 3` |
| 남동 | `N6:2:I.13` | `ESTOP / MainRoutine / Rung 3` |
| 북동 | `N6:2:I.14` | `ESTOP / MainRoutine / Rung 3` |

이 두 비트는 각각 `Robot1 / Background / Rung 34`, `Robot2 / Background / Rung 4`의 HOLD 출력 조건에 사용된다. R#1은 타이머와 다른 운전 조건도 함께 확인하므로 값이 언제 바뀌는지는 그 조건도 함께 봐야 한다.

Vision으로 전달되는 두 신호는 다음과 같다. **주석에 FANCE라고 적혀 있지만, 확인된 로직에서 두 신호는 도어 입력을 직접 복사하지 않는다.** 각각 해당 로봇의 `i_fault`를 반전해 만든다.

| Cathode1 위치 | 전달 신호 | 만드는 조건 |
| --- | --- | --- |
| `Robot1 / Background / Rung 68` | `VISION_FANCE` → 전송 비트 `[0].24` | R#1의 `i_fault`가 0이면 1이다. |
| `Robot2 / Background / Rung 50` | `VISION_FANCE2` → 전송 비트 `[0].25` | R#2의 `i_fault`가 0이면 1이다. |

두 `i_fault`는 각각 `Program:Robot1.i_fault`, `Program:Robot2.i_fault`이며 서로 다른 로봇 입력이다. 로봇 교체 전후에 실제 어떤 신호가 이 입력으로 들어오는지 아직 확인되지 않았다. 이름만 보고 도어 열림을 나타낸다고 판단하지 않는다.

Vision PLC의 `MainProgram / ALARM / Rung 18`은 수신 비트 `[0].24`와 `[0].25`가 **모두 0**일 때 `ALARM.12`를 1로 만든다. `MainProgram / ROBOT / Rung 6`은 `ALARM.12`를 비롯한 조건을 확인해 `ROBOT4:O1.Output[0].1`을 제어한다. 이 출력에는 R4 HOLD라는 설명이 붙어 있다.

Cathode1의 별도 경로도 있다. `ESTOP / MainRoutine / Rung 22`에서 `ESTOP`을 만들고, Rung 23에서 `R4_o_ESTOP`을 만든다. 이 신호는 Vision의 `Program:MainProgram.i_csm_E_Stop`으로 전달되며 같은 R#4 HOLD 렁에서 사용된다. 확인한 Rung 23에는 세 도어 입력이 직접 들어 있지 않다. `ESTOP`은 비상정지 계통과 HMI 입력을 읽는 신호이므로 이름만으로 실제 안전 배선을 판단하지 않는다.

## 어디가 부족할 수 있나

1. 도어 열림으로 R#1·R#2 HOLD가 바뀌더라도 두 로봇의 `i_fault`가 반드시 바뀌도록 PLC에서 직접 연결되어 있지는 않다. 새 로봇에서 어떤 신호가 이 입력으로 전송되는지 확인이 필요하다.
2. Vision은 두 수신 비트가 모두 0일 때만 `ALARM.12`를 켠다. 하나만 0이면 이 알람은 켜지지 않는다.
3. `R4_o_ESTOP`은 세 도어 입력을 직접 확인하지 않는다. 문이 열려도 비상정지 계통과 HMI 조건이 그대로면 이 전송 신호는 유지될 수 있다.
4. R#4의 통신 HOLD 출력과 로봇 컨트롤러에서 실제로 받아들이는 입력이 맞는지, 별도의 안전 도어 정지 회로가 있는지는 현장 확인이 필요하다.

이는 보유한 프로그램을 읽어 확인한 경로다. 로봇 교체 전후의 설정이나 현장 신호를 아직 확인하지 않았으므로 어느 부분이 실제 원인인지는 확정하지 않는다.

## 점검 1: Vision PLC에서 네 값부터 기록한다

Studio 5000에서 Vision PLC를 Online 모니터한다. `ALARM.12`와 `i_csm_E_Stop`은 `MainProgram`의 프로그램 태그다. 화면에 프로그램 범위를 표시할 때는 `Program:MainProgram.ALARM.12`처럼 구분한다.

| 태그 | 확인 위치 | 확인할 내용 |
| --- | --- | --- |
| `zc_Vision_Read[0].24` | 컨트롤러 태그 | Cathode의 R#1 관련 전송 비트다. |
| `zc_Vision_Read[0].25` | 컨트롤러 태그 | Cathode의 R#2 관련 전송 비트다. |
| `Program:MainProgram.ALARM.12` | `ALARM / Rung 18` | 두 수신 비트가 모두 0일 때 1인지 본다. |
| `ROBOT4:O1.Output[0].1` | `ROBOT / Rung 6` | R#4 HOLD 관련 출력의 변화를 본다. |

보전·안전 담당자와 안전하게 격리한 뒤 세 문을 하나씩 확인한다. 각 문을 확인하기 전에 다른 두 문은 닫힌 상태인지 확인하고, 실제 0과 1을 기록한다. **아래 빈칸은 예상값이 아니라 현장에서 채울 기록란이다.**

| 도어 상태 | `.24` | `.25` | `ALARM.12` / R#4 HOLD 출력 |
| --- | --- | --- | --- |
| 세 문 닫힘 |  |  |  |
| 북서 문 열림 |  |  |  |
| 북동 문 열림 |  |  |  |
| 남동 문 열림 |  |  |  |

| 관찰 결과 | 다음에 확인할 곳 |
| --- | --- |
| 문을 열어도 `.24`, `.25`가 모두 1이다. | Cathode의 두 `i_fault`와 새 R#1·R#2 출력 매핑을 본다. |
| 두 값 중 하나만 0이다. | 현재 로직에서는 `ALARM.12=0`이다. 어느 로봇 신호가 바뀌지 않는지 본다. |
| 둘 다 0인데 `ALARM.12=0`이다. | Online의 `ALARM / Rung 18`, 해당 태그의 다른 쓰기와 프로그램 실행 상태를 확인한다. |
| `ALARM.12=1`인데 HOLD 출력이 1이다. | `ROBOT / Rung 6`, 태그와 출력의 다른 쓰기, 실행 상태를 확인한다. |
| HOLD 출력이 0인데 로봇이 정지하지 않는다. | R#4 컨트롤러의 실제 수신값, HOLD 매핑과 설정을 확인한다. |

## 점검 2: Cathode1 PLC에서 도어 입력과 로봇 신호를 확인한다

첫 점검에서 수신 비트가 기대와 다르면 아래 여덟 값을 모니터한다. 8개씩 기록해야 하는 Trend에서도 한 화면에 들어간다. 프로그램 태그의 범위를 반드시 구분한다.

| 태그 | 형식 | 확인할 내용 |
| --- | --- | --- |
| `N4:2:I.15` | 디지털 | 북서 도어 입력이다. |
| `N6:2:I.13` | 디지털 | 남동 도어 입력이다. |
| `N6:2:I.14` | 디지털 | 북동 도어 입력이다. |
| `Robot1_ESTOP` | 디지털 | 세 도어를 읽어 만든 R#1 조건이다. |
| `Robot2_ESTOP` | 디지털 | 세 도어를 읽어 만든 R#2 조건이다. |
| `Program:Robot1.i_fault` | 디지털 | 새 R#1에서 들어오는 입력이다. |
| `Program:Robot2.i_fault` | 디지털 | 새 R#2에서 들어오는 입력이다. |
| `R4_o_ESTOP` | 디지털 | Vision의 `i_csm_E_Stop`에 전달되는 비트다. |

이름에 ESTOP이 들어간 태그의 1과 0은 각각의 렁에서 해석한다. 현장에서 문 열림·닫힘에 따른 입력 극성을 먼저 확인한다. Trend는 펄스가 샘플 사이에 지나가면 놓칠 수 있으므로, Online 화면과 점검 기록도 함께 사용한다.

## 점검 3: 로봇과 안전회로를 확인한다

보전 담당자에게 새 로봇 설정에서 다음 내용을 확인해 달라고 요청한다.

- R#1과 R#2가 도어 개방 또는 HOLD 상태일 때 Cathode PLC의 각 `i_fault`에 실제로 어떤 값을 보내는가?
- R#4에서 Vision PLC의 HOLD 출력에 대응하는 신호를 어디로 받고 있으며, 해당 입력은 사용 설정되어 있는가?
- 세 도어의 안전 스위치가 안전 릴레이 또는 안전 제어 장치를 거쳐 R#4의 실제 안전 입력까지 연결되어 있는가?
- 문을 닫았을 때 로봇이 어떻게 복귀하며, 별도의 리셋과 시작 조작이 필요한가?

도어 개방 시 안전 정지와 재시작 방지는 제어 경로 전체에서 확인해야 한다. [Rockwell Machinery Safebook 5](https://literature.rockwellautomation.com/idc/groups/literature/documents/rm/safebk-rm002_-en-p.pdf)는 가드가 열렸을 때 위험 동작을 정지하고 문을 닫는 것만으로 재시작하지 않도록 하는 안전 기능을 설명한다.

## 기록을 전달할 때

도어별 네 값, Cathode의 여덟 값, 로봇의 운전 모드와 알람 표시, 확인 일시를 함께 기록한다. 값이 변하지 않았다면 그 사실도 적는다. 실제 배선과 로봇 설정이 확인되기 전에는 PLC 접점을 추가하거나 HOLD만으로 안전 정지가 해결됐다고 판단하지 않는다.
