시험안 결론

Robot3와 SC1 파라미터는 건드리지 않고, SC1 이동이 시작된 뒤 완료되기 전까지 신규 Robot Unload 허가만 제한한다.

1차 시험에서 변경하는 것

  • Sheet_Conveyor_1 / Permits / Rung 6 한 곳
  • HMI Enable=1, AUTO, active=1일 때만 신규 Robot 진입 차단
  • active=0이면 추가 Gate 해제
  • Manual과 Off에서는 기존 조건 유지

1차 시험에서 변경하지 않는 것

  • HMI Enable=0의 기존 운전
  • Robot3 LS 프로그램과 티칭 좌표
  • SC1 속도와 거리 파라미터
  • Tracking, MES, Reject 구조
적용 상태 이 문서는 소스 교차검토가 끝난 1차 시험안이다. Studio 5000 Verify, Online Trend, 저속 현장시험 전에는 생산 확정본으로 취급하지 않는다.

기존 허가 조건 뒤에 HMI, 운전 모드, SC1 active 상태를 이용한 병렬 XIO Gate를 추가한다.

정확한 표현 Enable, AUTO, active가 모두 1일 때만 Robot3 신규 진입을 차단한다. 세 Tag 중 하나라도 0이면 추가 Gate는 통과한다.

pending, active, permit_run_forward

세 신호는 서로 다른 일을 한다. active는 모터 출력이 아니라 미완료 SC1 전진 사이클의 상태 표시이다.

sc1_start_req_pending

요청 기억

SM1 또는 SM2에서 전진 요청이 들어왔다는 사실을 래치한다. 아직 SC1이 출발하지 못한 대기 상태에서도 1일 수 있다.

sc1_start_req_active

출발 완료 전

SC1이 Forward Step에 들어간 뒤 1이 되고, 목표 Count와 State_Stop 완료가 확인될 때까지 유지된다.

permit_run_forward

실시간 모터 허가

Robot3 Clear 상태에 따라 SC1 전진 전압을 허가한다. 이 신호가 끊기면 일부 전진 속도 모드에서 전압이 0이 될 수 있다.

쉽게 구분하기

pending / active / permit

pending은 주문 기억, active는 출발 후 도착 전, permit_run_forward는 지금 실제로 움직여도 되는지에 해당한다.

XIO 병렬 OR Gate 읽는 방법

병렬이므로 OR 조건이 맞지만, XIO는 Tag가 0일 때 참이다. Tag 값과 접점 통과 상태를 반대로 읽지 않아야 한다.

XIO 기본 동작

Tag 값XIO 접점결과
0TRUE / 닫힘통과
1FALSE / 열림차단

병렬 Gate 논리

NOT HMI
OR NOT AUTO
OR NOT active

드모르간 법칙으로 정리하면 NOT(HMI AND AUTO AND active)이다.

깔딱 후 자동 재전진 원리

active가 모터를 직접 돌리지는 않는다. SFC와 요청 상태가 미완료 사이클을 기억하고, Robot Clear 복구 후 permit_run_forward가 다시 전압을 허가한다.

1
SC1 전진 중
SFC Step, var_cmd_speed, pending, active가 미완료 사이클을 유지한다.
2
Robot3 조기 진입
Robot3가 Infeed 영역으로 들어가면 i_clear_of_infeed가 0이 될 수 있다.
3
전진 허가 상실
z_permit_r3_sc1_start와 permit_run_forward가 0으로 바뀔 수 있다.
4
모터 전압 0
var_cmd_speed 2, 1, 3 조건에서 permit_run_forward가 없으면 BasicControl은 0 V 경로로 갈 수 있다.
5
Robot Clear 복구
Robot이 빠져나가 Clear가 1이 되면 permit_run_forward가 다시 1이 된다.
6
자동 재전진
유지된 SFC와 var_cmd_speed에 따라 전압이 다시 출력되고 SC1이 계속 전진할 수 있다.
근거 상태 위 피드백 경로는 L5X에서 확인된다. 실제 깔딱 순간마다 같은 순서가 발생했는지는 i_clear_of_infeed, permit_run_forward, var_cmd_speed, var_volts_velocity와 SFC State를 같은 10 ms Trend로 기록해야 최종 확정할 수 있다.

Robot3 프로그램 확인

PLC Gate의 목적은 이미 진입한 Robot을 중간 정지시키는 것이 아니라, SC1 완료 전 신규 Unload 호출을 시작하지 않게 하는 것이다.

CSM1 호출 흐름

RSR0001 /MN 24
IF DI[1:Unload Infeed]=ON,CALL ULOD_INF;

ULOD_INF /MN 14
DO[1:Clear of Infeed]=OFF;

ULOD_INF /MN 16
J PR[2:Infeed Perch] 100% CNT100 ACC150;

판단

  • DI[1]이 ON이면 Robot 메인에서 Unload 서브프로그램을 호출한다.
  • 호출 후 서브프로그램은 DI[1]을 매 Step 다시 확인하지 않는다.
  • PLC 출력이 뒤늦게 OFF되어도 이미 들어간 Robot을 취소하지 않는다.
  • 따라서 신규 호출 이전에 Gate해야 한다.

필수 시험 절차

Enable=0은 원본 등가성만 확인하고, 개선 효과는 Enable=1에서 SM1과 SM2를 각각 시험한다.

원본 회귀

  • HMI Enable=0에서 AUTO, MANUAL, OFF 동작이 원본과 동일한지 확인
  • active=1이어도 추가 Gate 때문에 Robot 허가가 차단되지 않는지 확인
  • Enable=0에서는 깔딱 제거 효과를 판정하지 않음

Enable=1 AUTO

  • SM1 Drop 최소 10 Cycle
  • SM2 Drop 최소 10 Cycle
  • active=1 동안 z_permit_sc1_r3_unload=0 확인
  • active=0 이후 기존 Robot 허가 복원 확인

기존 Sheet 대기

  • pending=1, active=0에서 기존 Sheet를 Robot이 먼저 Pick하는지 확인
  • 전송 위치가 비워진 후 SC1이 정상 시작하는지 확인
  • Robot과 SC1의 상호 대기가 없는지 확인

복구와 모드 전환

  • Enable=1 MANUAL과 OFF 기존 동작
  • AUTO 이동 중 MANUAL 또는 OFF 전환
  • Single Cycle, Reset, Home Recovery
  • Sheet, Grade, Tracking Data 정합성

합격 및 즉시 원복 기준

필수 합격

  1. Enable=0에서 원본과 동일
  2. Enable=1 AUTO active=1 동안 Robot Unload 허가 0
  3. active=0 이후 기존 Robot 진입 정상 복원
  4. SM1과 SM2 각각 10 Cycle 이상 깔딱 없음
  5. Sheet, Grade, Tracking Data 일치
  6. 새 Fault, Alarm, 물리 간섭 없음

즉시 중단 및 원복

  1. Enable=0 동작이 원본과 다름
  2. Enable=1 active=1인데 Robot 허가가 1
  3. active=0 이후 Robot 허가가 복원되지 않음
  4. 전송 위치 기존 Sheet에서 상호 대기 발생
  5. Manual, Off, Reset, Home Recovery 이상
  6. Sheet와 Data가 한 칸이라도 어긋남
