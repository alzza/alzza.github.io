이 설명서는 화면의 영문 이름을 그대로 병기하여 메뉴를 찾을 수 있게 구성했습니다. 기본값은 저장된 설정이 없는 경우를 뜻합니다. 이전 버전에서 설정을 가져온 기기는 값이 다를 수 있습니다.

프로젝트는 연구·시험용 CAN 펌웨어입니다. 특히 운전자 감시, 차선 변경, 조향 토크 관련 메뉴는 차량이 받는 신호를 바꿉니다. 아래 내용은 기능의 의미를 설명하는 문서이며, 운전자 감시를 대신하거나 차량의 안전 기능을 보장하지 않습니다. 위험 기능은 원본 화면의 경고도 함께 설명했습니다.

1. 먼저 알아둘 용어와 화면 구조

1.1 공통 용어

화면 용어 한글 뜻 읽는 방법
AP / AUTOPILOT 오토파일럿 상태 단순히 스위치를 켰다는 뜻이 아니라 수신한 차량 상태입니다.
AUTOSTEER / NOA / FSD 오토스티어 / 내비게이션 기반 오토파일럿 / FSD 기능별로 허용하는 상태가 다릅니다. 모든 AP 기능이 FSD에서도 작동하는 것은 아닙니다.
NAG / Hands-On / HO 운전자에게 조향 참여를 요구하는 경고 / 손 감지 관련 값 HO 숫자는 CAN 신호값입니다. 카메라가 주시를 확인했다는 뜻으로 해석하면 안 됩니다.
ALC / ULC 자동 차선 변경 / 화면에서 사용하는 ULC 차선 변경 관련 제어 비슷한 이름이어도 아래의 확인 요청·고속도로 외 허용·사각지대 설정은 서로 다른 필드를 바꿉니다.
STOCK 차량이 원래 보내는 값 유지 OFF와 다릅니다. STOCK은 원래 값이 ON이면 그것을 유지할 수 있습니다.
RX / TX 수신 / 송신 RX는 받은 메시지, TX는 보낸 메시지입니다.
TX OK / FAIL 송신 성공 / 실패 집계 송신 API가 성공했다는 뜻이지 차량이 의도한 동작을 했다는 증거는 아닙니다.
Gate / Blocked 허용 조건 / 조건에 막힘 AP 상태, 신호 유효성, 통신 복구 등의 조건 때문에 송신하지 않는 상태입니다.
Template / Fresh / Stale / Age 원본 메시지 / 최신 / 오래됨 / 경과 시간 원본 메시지를 받아야 값을 일부 바꿔 보낼 수 있습니다. 허용 시간은 기능마다 다릅니다.
NVS / Saved / Persistent 전원을 꺼도 남는 저장소 / 저장됨 재부팅 뒤에도 설정이 유지됩니다.
RAM-only / Session / Volatile 임시 저장 / 현재 세션 재부팅하면 사라집니다. PedalMap은 P 진입 확인 때도 해제됩니다.
CAN A / CAN B 보드의 두 CAN 통신 경로 A는 MCP2515, B는 ESP32 TWAI입니다. 실제 연결 버스는 차량 프로필에 따라 달라집니다.
BUS OFF CAN 오류 누적으로 통신에서 이탈한 상태 기능 OFF와 다릅니다. 진단 화면의 오류·복구 기록을 확인하는 상태입니다.
ms / s / Nm 밀리초 / 초 / 뉴턴미터 1,000 ms = 1초. Nm 표시는 토크 신호 크기이며 실제 조향 명령과 동일시하면 안 됩니다.

1.3 설정을 적용하는 방식

스위치·선택 버튼은 대부분 변경 즉시 장치로 전송됩니다. 숫자 입력 옆에 Apply, Apply Delay, Apply Mode H Tuning, Save Labels가 있으면 입력 후 해당 버튼까지 눌러야 합니다. Unsaved는 아직 저장되지 않았다는 뜻입니다. 실패 안내가 뜨면 화면에 적힌 숫자만 보고 적용됐다고 판단하지 마세요.

2. 첫 연결과 차량 프로필

2.1 Wi-Fi 접속

  1. 휴대전화 또는 PC에서 기본 Wi-Fi 이름 T2CAN-****에 연결합니다. 이름을 변경한 기기는 변경된 이름을 사용합니다.
  2. 기본 비밀번호는 12345678입니다. 변경한 기기는 기존에 설정한 비밀번호를 사용합니다.
  3. 브라우저에서 http://192.168.4.1을 엽니다. 인터넷 연결이 아니라 보드의 로컬 대시보드 접속입니다.
  4. 첫 실행이면 PROFILE SETUP MODE에서 차량과 실제 CAN 배선을 선택합니다.

4. DEVICES — S3XY 버튼

4.1 Add Button — 버튼 등록

최대 3개를 등록합니다. 먼저 Wireless Settings → Bluetooth Master가 ON인지 확인합니다. + Add Button을 누르면 화면이 버튼을 계속 누르고 있으라고 안내합니다. Continue로 검색을 시작하며, 미등록 버튼이 하나면 자동 페어링하고 여러 개면 Select로 대상을 고릅니다. Connected가 표시된 뒤 버튼을 놓습니다.

Device found → Bluetooth connected → Securing connection → Preparing button은 검색·연결·보안·사용 준비 단계입니다. 완료 후 Done은 종료, Configure Button은 동작 배정 화면입니다. 새 버튼의 동작은 None으로 시작합니다. Scan Again은 재검색, Try Again은 실패한 등록 재시도입니다.

Off-Highway ALC와 ULC Off-Highway는 이름이 비슷하지만 서로 다른 필드입니다. STOCK은 원본 유지, OFF는 해당 선택 필드를 끔으로 지정하는 뜻입니다. AGGRESSIVE·MAD MAX는 코드상의 모드 이름이며 실제 차간 간격이나 허용 위험도를 이 문서에서 수치로 보장할 수 없습니다.

INJECTION GATE는 Confirm-Free 조건, STOCK / FORCED BIT1은 원본/지정값, COMPOSITOR GATE는 공통 조합 송신 조건입니다. TX CAN B OK / FAIL, 0x3F8 TX OK / FAIL, Off-Highway TX OK / FAIL은 해당 송신 집계입니다. RX age, bit1 / Hz / age / RX, raw는 원본의 최근성·주기·내용이며, Gate-blocked는 조건 때문에 생략한 프레임 수입니다.

이름은 감시 해제를 뜻하지만, 코드에서 확인되는 동작은 0x3FD mux1 bit43을 0으로 지정하는 것입니다. 카메라 기반 DMS나 NAG 전체가 실제로 비활성화됐다고 단정할 수 없습니다. 차량 세대·소프트웨어별 효과는 별도 검증 대상입니다.

기본 OFF이며 선택은 NVS에 저장됩니다. 모든 유효한 현재 3/Y·Y L 프로필의 R79 경로에서 허용됩니다. LAB OFF이면 적용은 중단되지만 저장 선택은 남습니다. SAVED는 선택이 저장됐다는 뜻이고, 차량 감시 해제 성공 표시가 아닙니다.

19. LAB → Driver Monitoring Capture — 운전자 감시 신호 기록

모든 차량 프로필에서 두 버스의 0x389 / 0x5D9 / 0x247 / 0x399 / 0x370을 관찰하는 RX 전용 도구입니다. 고정 시간은 PRE 2초 + POST 5초, 실제 코드의 보관 한도는 12구간·2,048표본이며 사전 버퍼는 512표본입니다. 초기 정적 HTML에는 1,024가 남아 있지만 상태 응답은 코드의 2,048을 전달하므로 연결 후 갱신된 용량을 기준으로 읽습니다.

아래 A–F는 기록에 붙이는 상황 라벨입니다. 실제 도로에서 주시를 분산시키라는 사용 지시가 아닙니다.

라벨 화면 영문 한글 의미
A FRONT · NORMAL 정상적인 전방 주시 상황
B SCREEN GLANCE 화면을 잠깐 보는 상황
C SIDE LOOK 옆을 보는 상황
D LOOK DOWN 아래를 보는 상황
E TORQUE + LOOK AWAY 조향 토크 입력과 다른 방향 주시가 함께 있는 상황
F FRONT · NO TORQUE 전방을 보되 의도적인 조향 토크 입력이 없는 상황

DRIVER INTERACTION은 해석한 상호작용 상태, CAPTURE STATE, SEGMENTS/MAX, SAMPLES/CAPACITY, REMAINING POST는 기록 진행 정보입니다. PRE BUFFER WARMUP은 사전 기록 버퍼를 채우는 중이라는 뜻입니다.

각 ID의 bus / age / count / raw는 버스·경과 시간·횟수·원시 바이트입니다. 0x399 DAS hands-on, 0x370 EPAS hands-on / torque는 참고 해석값입니다. Last interaction transition은 최근 해석 상태 전환, Requests / ignored / dropped는 요청·누락 집계, Storage는 저장 공간 상태입니다.

Download Driver Monitoring CSV로 자료를 저장하고, Reset Driver Monitoring Capture로 현재 기록을 지웁니다. 원시 바이트와 CAN A/B·버스 역할 기록이 근거이며, 화면의 주시·HO 해석은 연구용 추정입니다. 기록기가 RX 전용이라는 사실은 별도로 켜져 있는 다른 주입 기능까지 OFF라는 뜻은 아닙니다.
